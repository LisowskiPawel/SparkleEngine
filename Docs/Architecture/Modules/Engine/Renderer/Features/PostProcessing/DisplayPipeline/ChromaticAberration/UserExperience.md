# Chromatic Aberration Experience Contract

[Docs](../../../../../../../../README.md) / [Up](ChromaticAberrationDesign.md)

**Status:** target experience for the approved basic effect; not implemented UX or acceptance evidence.

## Product Promise And Boundary

The approved release has chromatic aberration On in presented Lit/realtime output. Exact strength/center/start values are frozen in CHRD-00 before implementation; this page invents none. Raw Reference, exact diagnostics and UI retain their bypass rules. Neutral/Off is a numerical and no-work control, not the shipped default.

Rendering settings belong to the existing Editor owner; Game consumes the same persisted settings. The release [control contract](../../../../../../../../Acceptance/FirstRelease.md#baseline-and-selection) requires no separate Game settings frontend and no new public lens-effect toggles. Internal/default parameters and view isolation are necessary for correct rendering, not permission to build another control panel.

## First Use And Active Truth

Launch the selected map through the existing product journey and observe the approved default. Existing configuration/capture information identifies actual model/parameters, frame/view, target-linear domain, extent and candidate when that evidence is needed. The effect is intentional only when this real lineage matches; ordinary reconstruction/filtering fringes remain defects.

A developer verifies a neutral comparison through the existing typed settings/view or disposable validation route with the same scene/frame/extent. Do not implement an Off toggle, strength/center/start sliders, inheritance widget or dedicated status read model merely to run that check. Any later public control needs a separate consumer/scope decision.

## Defaults, Reset And Validation

| Action or state | Required result |
| --- | --- |
| Product settings Reset | Restore approved shared defaults, including the effect On and its frozen values. Do not silently reset the release to Off. |
| Explicit neutral validation | Zero strength/Off schedules no effect pass, resource or copy and preserves exact pixels; it does not change shipped defaults. |
| Active frame | Use that view's actual rectangle/extent and frozen units; preserve alpha, stage/product and raw/debug/UI isolation. |
| Invalid/nonfinite or out-of-range request | Reject before recording, preserve the accepted state and report the failing value/reason through the existing route; no plausible silent default. |
| Missing required program/input or stale generation | Fail or report the owned unavailable boundary truthfully; no stale/partial output or false active result. |
| Resize, minimize, two views or later valid request | Resolve current immutable values once, reject stale prepared work and keep view identities isolated. |
| Close/shutdown | Existing frame/product owners settle; this stateless effect adds no worker, history, device wait or shutdown service. |

Persistence, where an existing selected setting is persisted, uses the current per-user owner and format. There is no new migration reader or public settings-compatibility surface for an unexposed parameter.

## Evidence And Automation

AC-CHR-05/06/08 and mapped checks exercise actual request-to-frame truth, configured defaults/reset, neutral identity, invalid/unavailable recovery, two-view/resize, raw/pre/post/encoded capture lineage and package behavior on both APIs. Use the current automation/capture request and original artifact schema; metadata is not another collector or UI state authority.

An On/neutral comparison records both actual parameter identities and any frame/scene/extent mismatch. Captures may contain private paths/content and stay local under current privacy policy. A screenshot alone proves neither the intentional source of a fringe nor correct sampling/order/alpha.

If an existing admitted control is used, its text/units/range/default/error must be clear with keyboard and supported DPI/locale behavior. This condition does not require implementing controls that the product scope defers. A qualified HDR tuple is required for actual HDR-output claims; SDR evidence cannot silently close that cell.

There is no dedicated lens onboarding, support service, toggle inventory or state/action screen program. [Semantics](Semantics.md), [execution ownership](ExecutionArchitecture.md) and the [remaining plan](ImplementationPlan.md) own the algorithm, lifecycle and delivery order.

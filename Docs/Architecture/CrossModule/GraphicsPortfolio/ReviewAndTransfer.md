## Small Reader Package

Prepare the existing portfolio artifact destination with: one short landing/readme; three concise case narratives; original-artifact index with hashes/rights/redaction state; reproducible command/expected-result instructions; a short technical paper and talk/demo outline; review/feedback dispositions. Reuse the accepted manifests and reports, rather than copying large captures into source or creating a new results schema/service. Private dumps/symbols and uncleared assets do not become shareable by inclusion in an index.

[Evidence folders](../../../Acceptance/GraphicsWorkloads.md#evidence-folders-and-delivery-owners) owns the candidate layout: original technical records stay in their subject homes; the small portfolio packet and CASE-05 reproduction/transfer folders reference them. [Technology Transfer](TechnologyTransfer/TransferDesign.md) and its [KT-0..3 plan](TechnologyTransfer/ImplementationPlan.md) own M7 exercise execution; this page keeps the shared review criteria.

Each case answers: problem/consumer, constraints, your personal contribution, derivation and alternatives, source/API/data/lifetime design, observed result, failure/negative evidence, limitation, reproduction and what became simpler. Team/paper/library credit stays explicit. The recruiter path is 60-90 seconds, manager path 10 minutes, specialist path 45-60 minutes; use existing Requirements reading targets rather than separate portfolios.

## Binary Review Criteria

| Criterion | Required observable evidence |
| --- | --- |
| `AC-PORT-01` Technical coverage | The three cases join every applicable PGE-01..15 portfolio facet to original evidence or an explicit external/non-repository boundary. Source-only, unrun and excluded claims are visibly distinguished. |
| `AC-PORT-02` Numerical and execution trust | A specialist can follow one estimator/model rule to source, cooked artifact and actual native result; independently recompute a reported comparison and find its failure control/uncertainty. No pooled metric or beauty image replaces raw proof. |
| `AC-PORT-03` Documented M6 reproduction | The author or agent uses the exact cleared candidate/instructions and obtains the declared result without private repairs. Record prior involvement, environment, interventions, failed steps and actual output; assisted teaching is not an unaided pass. |
| `AC-PORT-04` Technical direction and review | The author or agent challenges a meaningful design/performance assumption in a separate review pass. Retain the original proposal, evidence, alternative, decision and resulting revision or reasoned rejection, with personal attribution. A separate author/agent review pass is accepted; identify the actual reviewer and test the challenged claim. |
| `AC-PORT-05` M7 transfer in a second context | A second actual consumer context uses the result or method: a distinct workflow, project integration, research/tool use or explanation exercise, executed by the author or agent. Freeze that consumer's constraint and expected task before the exercise. It need not create a new engine, SDK or feature. |
| `AC-PORT-06` Teaching and feedback-driven follow-through | Deliver a bounded explanation/exercise, retain the rehearsal task/decision before and after, findings and a justified revision or evidence-backed no-change decision. Recheck the affected result after revision; a self-run exercise must not be described as observed third-party learning. |
| `AC-PORT-07` Shipped/maintainable judgment | Show repeated completed slices, simplification/retirement decisions, the incident response and the actual released/reproduced scope. State who owns follow-up and when the finite exercise ends; invent no support service or maintenance deadline. |
| `AC-PORT-08` Honest public/external claims | Rights/privacy and author/team credit are checked. Employment duration, degrees, proprietary shipped scope, organizational leadership and travel/communication facts use truthful CV/reference/interview records; the repository cannot certify them. |

M6 closes the technical package and first reproduction (`01..03` plus its separate review). M7 closes the direction/second-context/teaching/revision record (`04..08`) for the stronger principal-oriented portfolio claim. These are local program choices inferred from the role study, not an NVIDIA hiring guarantee or official checklist.

Assembly consumes M3's locally qualified study/incident packet and NG-S6a's local evaluation/package result, with final rehearsal cells visibly open. The actual M6 exercise covers the study/analysis and neural results required by AC-WS-04/AC-NG-08; WS-S4/NG-S6b then reuse those observations to close their criteria. Requiring those adoption verdicts before assembly would create a prerequisite cycle. One frozen package/participant may cover the distinct results; a successful unrelated headline cannot substitute for either.

## Failure Controls And Check Route

Before review, deliberately identify one wrong/missing candidate link or hash, a hidden prerequisite, a mixed-settings comparison and an uncleared artifact; the preparation check must reject them. Restore the valid package before the recorded author/agent rehearsal. Use existing manifests/commands and disposable probes, not a portfolio test framework.

`CHK-PORT-01` checks case-to-original-evidence/rights/claim coverage and the three timed reader paths. `CHK-PORT-02` is the actual documented reproduction with no author repair. `CHK-PORT-03` records expert challenge, second-context exercise, learning/feedback and the justified revision/retest. `CHK-PORT-04` reconciles final claims/attribution and non-repository evidence. Record failures and the actual rehearsal actor honestly in the existing CASE/WL/portfolio record; this is not a second runtime readiness ledger.

If numerical proof, rights, a valid input or an executed required rehearsal is missing, keep that criterion open. An external participant is optional. An available artifact or attempted contact is not adoption. No fictional partner, recommendation, mentor outcome, public talk or upstream acceptance is permitted.

## Contact, Publication And Upstream Scope

Prepare the concrete cleared package, exercise and recipient question before requesting any external action. Contact, publication, issue/PR submission and use of another person's identity need their actual authorization; this plan sends nothing. Public upstream work remains conditional on a real evidenced issue and recipient policy. A rejected contribution can support honest feedback evidence, but does not establish adoption or satisfy a missing technical product.

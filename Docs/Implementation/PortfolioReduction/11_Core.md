## Outcome and ownership

Keep neutral mechanisms and make product layout authority small and explicit; remove Windows-irrelevant policy without turning Core into product orchestration.

**Retain:** CVar execution, category logging, events/subscriptions, child-process supervision, path containment/publication, UTF-8/JSON/hash mechanisms and their concurrency/lifetime contracts.

**Target flow:** Host/product composition selects roots -> neutral Core values/mechanisms validate and operate -> domain owners interpret products/results. Core has no Editor/Renderer dependency.

Dominant execution owner for: CO-01, CO-02, CO-03, CO-04, CO-05, CO-06. Cross-module deletion/refactoring is authorized for this owner's complete system; keep touched module dependency/lifetime rules.

## Adapt the surviving design

- **Product policy leaves Core:** after non-Windows fallback and general root-discovery cuts, composition supplies the selected product/workspace roots once. Core validates explicit paths and provides neutral filesystem/process/publication mechanisms; remove competing discovery caches, project selection and forwarding APIs from consumers. Keep a single authority without a new global service locator.
- **Narrow actual mechanisms:** reshape callers around explicit inputs/results and existing retained library facilities. Keep logging/CVar/event/process ownership and concurrency boundaries cohesive; remove a wrapper or duplicate store only when the full caller chain no longer needs its invariant. No broad rewrite of retained foundation contracts is authorized by this stage.

**Structural acceptance:** trace Launcher, host and tool startup to the same root authority, including explicit overrides, missing paths, containment and DLL callers. Show no upward Core dependency or hidden duplicated roots. Moving discovery elsewhere unchanged or scattering fixed paths through callers fails.

**Reference application:** [P1 and P3](README.md#reference-choices-and-limits) guide narrow public/private contracts and explicit composition, not a universal engine-services layer.

Apply the [shared before/after design gate](README.md#reshape-the-surviving-design) within the existing owning stages; these requirements do not authorize additional feature cuts.

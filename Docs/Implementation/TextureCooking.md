## Current boundary and required behavior

[TextureCooker CMake](../../Tools/Cooking/TextureCooker/CMakeLists.txt) and [Compressonator acquisition](../../CMake/Dependencies/FetchDependencies.cmake) are the build authority. Current code is `AssetCooker` request generation → `TextureCooker cook-request-file` → source loading → policy/processing → staged cooked asset → batch publication → Renderer loading and RHI upload.

Source inspection found gaps between the migration requirements and the current implementation:

- [Source dispatch](../../Tools/Cooking/TextureCooker/Private/SourceLoading/TextureSourceLoader.cpp) accepts DDS, EXR, HDR/HDRI and the raster extensions below. It has no KTX branch. Optional KTX dependency registration does not establish an end-to-end source path.
- [DDS loading](../../Tools/Cooking/TextureCooker/Private/SourceLoading/DdsTextureSourceLoader.cpp) rejects 2D arrays and expects a DX10 cubemap `arraySize` of six. Correct container metadata conventions and face ordering need fixtures; the local convention is not a standard-format oracle.
- [Compressed-source processing](../../Tools/Cooking/TextureCooker/Private/Pipeline/Stages/EncodeStage.cpp) passes blocks through, optionally strips mips or changes color-space metadata, and rejects Generate with only one source mip. It does not run the uncompressed channel/filter/encoding path.
- [Batch execution](../../Tools/Cooking/TextureCooker/Private/Cooking/TextureCookBatchExecutor.cpp) uses up to four background workers. The [memory limiter](../../Tools/Cooking/TextureCooker/Private/Cooking/TextureCookMemoryLimiter.cpp) reserves source pixel payload after loading; the 1 GiB reservation is not a measured bound on decoder, float working-mip, encoder or GPU memory. No cancellation token reaches the current per-image processing call. Trace actual caller/process cancellation in stage 1.

Record these as existing limits or defects, separately from supported behavior. KTX and arrays remain required delivery checks under this request; implement the bounded path through upstream facilities and verify runtime use before claiming them. Do not silently reduce the requested scope to match the baseline. Resolve format discrepancies through standard fixtures and the actual consumer, without retaining legacy aliases or two output formats.

| Contract | Preservation and comparison requirement |
| --- | --- |
| Regular and Kaiser | Regular currently uses stb float box filtering with clamp edges. Kaiser is windowed sinc with support 3 and beta 6.5 in [ImageOps](../../Tools/Cooking/TextureCooker/Private/Pipeline/ImageOps.cpp). Compare support, weights, phase, normalization, ringing and border samples. NVTT sample defaults are not the Sparkle parameters. |
| NormalAware | [MipStage](../../Tools/Cooking/TextureCooker/Private/Pipeline/Stages/MipStage.cpp) decodes RGB from [0,1] to [-1,1], sums each 2×2 footprint, normalizes the vector and re-encodes it; alpha is averaged separately. The near-zero threshold is `1e-6`. Capture degenerate normals and odd-size footprints. A slope-space filter, height-to-normal conversion or color average alone is not equivalent. |
| Mip policy | Generate rebuilds from the top uncompressed level, halving each axis with a minimum of one until 1×1. PreserveExisting processes supplied levels without inventing others; NoMips keeps the top level. Capture compressed pass-through separately. Preserve all three policies on every required source/shape, including sub-4×4 tails. |
| Color and channels | Keep color-space intent separate from `Linear`/`SrgbLinearize` processing. Match when RGB is linearized and encoded; alpha and material data remain linear. Channel extraction replicates the selected channel to RGB and sets alpha to one. Preserve RGBA/BGRA order, normal orientation and group-specific format selection. Prevent upstream automatic gamma, ICC, premultiplication or alpha-coverage changes from altering the declared policy. |
| Alpha and BC1/BC4/BC5 | Current color groups choose BC1 for opaque byte color and uncompressed output for meaningful alpha; scalar grayscale groups choose BC4, normals BC5. Preserve these decisions, thresholds and alpha values rather than enabling BC1 cutout or another codec by default. Match unsigned generated BC4/BC5, two-channel normal layout, edge-block replication and existing signed-format pass-through. |
| HDR and BC6H | Current float/HDR groups select unsigned BC6H and clamp negative RGB to zero before half conversion; uncompressed RGBA32F has a different range/alpha contract. Compare values above one, negative inputs, half-range extremes, infinities/NaNs and alpha treatment explicitly. No tone mapping, exposure change or hidden sRGB clamp. Signed BC6H is an evaluated capability, not an existing promise or a silent replacement for UF16. |
| Sources and shape | Exercise `.dds`, `.exr`, `.hdr/.hdri`, `.png`, `.jpg/.jpeg`, `.bmp`, `.tga`, `.gif`, `.psd`, `.pic`, `.pnm/.ppm/.pgm`. Stage 1 fixes the required KTX1/KTX2 encodings, including the treatment of supercompression. Required shapes are 2D, 2D arrays and six-face cubemaps. Preserve accepted decoder behavior, supplied mips, face order/orientation, dimensions and pitches through upload. Cube arrays, volumes, animated images and arbitrary multipart/deep EXR are not implied by an extension or upstream capability. |
| Unsupported requests | Preserve actionable failure and accepted output. Audit the declared Angular filter and all validation paths; the migration must not accidentally advertise angular convolution, volume textures or other unimplemented processing. Additional source/codec support needs an explicit tested entry. |

Keep the current [`.stex` cooked asset contract](../../Engine/RHI/Public/Textures/CookedTextureAsset.h), asset IDs, output paths and material references for this delivery. The small metadata/payload writer is retained ownership, not retired processing. Normalize upstream DDS/KTX cube/array metadata into that contract once, and validate it through [cooked loading](../../Engine/Renderer/Private/Textures/CookedTextureLoader.cpp) and [upload](../../Engine/RHI/Public/Resources/RhiTextureUpload.h). A standard cooked-container redesign is separate work; do not add a new parser, representation version, compatibility path or runtime processing dependency here.

## Ownership after migration

Use these existing responsibilities directly. This table assigns decisions; it does not prescribe a class, service or file per row.

| Responsibility | Single authority and deduplication rule |
| --- | --- |
| Material/default intent and request identity | Existing producers choose explicit defaults and construct `TextureCookRequest`. The resulting request is authoritative; later stages do not infer material meaning again or overwrite it with SDK presets. Reuse genuinely shared rules while preserving intentional per-asset defaults. |
| Output codec, format and processor settings | TextureCooker's semantic policy chooses once from the request and decoded source properties. One translation supplies upstream settings. Callers and SDK automatic modes must not make competing output decisions. |
| Source decoding | The chosen processor, or one named upstream format provider for a proven gap. Route each source family once. A decode error remains an error; do not retry it through another local decoder. Retained format providers do not also become filter/encoder fallbacks. |
| Conversion, channel operations, filtering and encoding | The selected processor performs the mechanical work. Remove local equivalents and callbacks containing the old algorithms. CPU/GPU modes, if shipped, use the same semantic policy and processor. |
| Processing storage | Upstream-owned buffers are authoritative during processing; consumers borrow validated views where possible. Retain only necessary representation transfers, with explicit lifetime. Remove shadow mip trees, duplicate metadata caches and duplicated float/byte working copies. |
| Admission, cancellation and completion | The live TextureCooker batch owner and memory limiter govern admitted work and settlement using the existing task runtime. Bound upstream internal workers; do not add a second batch scheduler, queue, cancellation tree or progress controller. |
| Staging and accepted output | The existing `.stex` writer owns serialization/temporary-file I/O; `FileSetPublisher` alone owns generation commit/rollback. SDK callbacks write staging only and cannot publish accepted files or introduce another journal/manifest. |
| Dependency acquisition and selection | Existing CMake composition/cache owns pins and selected targets; Launcher reports readiness for that selection. Remove obsolete wiring and separately linked duplicate SDK copies. Upstream internal dependencies are counted as cost, not wrapped as new Sparkle systems. |

Use direct upstream calls. Do not introduce an `ITextureProcessor`, provider/factory registry, generic pipeline, parallel settings model or forwarding-only layer for one selected processor. Keep a helper only when it owns a real invariant or lifetime; reuse or simplify the existing owner first.

The stage 4 cutover removes the old production path in the same delivery. Keep baseline executables/artifacts in ignored comparison output, not behind a runtime switch, compatibility adapter or fallback. If coverage fails, leave adoption open rather than shipping two processors.

Deduplicate each rule at its owner. Preserve checks at distinct trust boundaries: request admission, external processor results and cooked-file loading still need their own guarantees. Reuse contract predicates instead of copying validators into callers or repeating checks throughout already validated pixel loops.

Run an oversize rejection and cancellation/settlement probe; a processor that cannot meet the admitted-work limits cannot be rescued by wrapping its call in another task. |

Stop a candidate's full trial at its first unmet mandatory gate and record the failing case/API or unavailable prerequisite. Compare a viable DDS-only scope separately where useful; do not integrate it as a partial fallback. For surviving candidates, extend the same case manifest with upstream API/settings, observations and projected files retired, then run the complete processor-level set. Real-cooker, fault-injection and GUI/native/package cells remain for stages 4–6. Unsupported/unrun cells stay explicit. This separates a fast no-go decision from a full replacement trial.

For Compressonator, start from the existing pin and compare a maintained release if needed. Inventory `CMP_Framework`, codecs, mip filters, image plugins, math/half, embedded stb and any SDK/GPU dependencies actually used. Determine whether required functionality needs SDK/Compute targets in addition to Framework/Core. Exclude GUI, Qt, mesh tools, unused codecs and optional GPU backends. Prove thread safety of plugin/global state or account for required serialization. Demonstrate additional retirement beyond today's `CMP_Core` calls; a new wrapper around block encoding earns no processing replacement claim.

For NVTT 3, obtain official SDK headers/libraries and compare its configurable Kaiser and decoded-normal operations directly. Establish whether parameters, odd sizes, clamp edges and near-zero vectors reproduce the baseline. Do not adopt the Exporter's slope-space filtering by default. Test forced CPU mode without a usable CUDA installation/device; if acceleration will ship, test GPU and allocation/fallback failure separately. Verify BC6H range/sign, imported runtimes, threading and redistribution files. Distinguish rebuilding Sparkle against a pinned SDK binary from rebuilding the SDK from source. Missing permitted acquisition, source availability required by the delivery contract, or redistribution terms is an adoption blocker; public sample licensing does not clear the SDK.

For DirectXTex, use DDS metadata/load, conversion, mip and whole-image compression APIs without runtime Renderer linkage. Compare CPU encoding first; its [GPU BC6H/BC7 path](https://github.com/microsoft/DirectXTex/wiki/Compress) is a separate D3D11/tool-device dependency. Measure WIC/non-WIC odd-size behavior and count EXR/KTX/raster providers. Do not map cubic/triangle to Kaiser or height-to-normal generation to NormalAware. If it only replaces DDS parsing, report files removed, cost and remaining filters/codecs as a DDS-only alternative.

Compare mips before BC encoding, then use an independent decoder so filter and encoder errors are distinguishable. An encoder's own decode or round-trip cannot be the sole oracle.

### Architecture and removal gate

The purpose is to return engineering attention to rendering, shader contracts and GPU analysis. The final diagnostic, cooker or Editor owner must expose its domain operation directly; understanding it must not require learning a replacement Sparkle JSON framework. Use supported upstream operations for grammar, lookup, conversion and serialization, and retain only the admission and domain rules that the library cannot supply. Do not wrap each former reader/writer method, preserve serialized intermediate models, or add generic convenience layers merely to hide library syntax.

Before conversion, settle the callback owner, target usage, exception translation and stage 1 duplicate policy. Use public upstream APIs; inspecting `nlohmann::detail` does not authorize depending on it. Keep callback state local to one parse, count object/array nesting and release keys when their object ends. Apply the common ownership rules; a substantial facade blocks adoption.

The release's [callback contract](https://github.com/nlohmann/json/blob/v3.12.0/docs/mkdocs/docs/features/parsing/parser_callbacks.md) makes `false` a filtering decision. It does not mean document rejection. In the [callback DOM implementation](https://github.com/nlohmann/json/blob/v3.12.0/include/nlohmann/detail/input/json_sax.hpp), key callbacks run before object insertion. Duplicate detection must therefore observe decoded keys during parsing, with separate key state for each active object. Throw an explicit admission error on a forbidden duplicate or excess depth and translate it at the owning operation boundary. For a documented optional-field fallback, record ambiguity before overwrite and let that owner ignore the ambiguous field after a successful complete parse; do not consume the collapsed value or reject unrelated optional fields. Keep this state local and bounded to the needed decisions, without a mirrored document or schema framework. Do not filter bad input into a successful partial document, inspect an already collapsed DOM for duplicates, or run a validation parse followed by a second DOM parse.

| Contract | Required implementation and discriminating cases |
| --- | --- |
| Duplicate keys | Required ambiguous members reject the owning document; optional ambiguous members follow the captured field fallback. Include mesh schema duplication → no metadata, displayName duplication → present metadata with empty displayName, and unaffected valid source retained. |

| Numbers in ignored fields | Exercise finite values such as `1e300` and valid JSON tokens beyond the library's storage range such as `1e999`. Preserve it through a supported API or prove a named paired range-policy change across all affected callers; add no repair lexer, second parse or compatibility parser. |
| Hashes and identity | Preserve each owner's string spelling, width, case/prefix acceptance and full-consumption hex validation. | Field conversion | Use const non-inserting lookup, explicit type/range checks and operation-local results; commit accepted state only after complete validation. Test a valid early field followed by an invalid required field with accepted state unchanged. Exercise missing/null/empty, root/container/element substitutions and optional ambiguity separately. Construct explicit objects/arrays, including empty ones; no generated mirror DTOs, broad defaulting or direct partial get_to into accepted state. |
| Whole-document admission | Parse a bounded complete byte range once; require the expected root type. Use strict [`parse`](https://github.com/nlohmann/json/blob/v3.12.0/docs/mkdocs/docs/api/basic_json/parse.md), not stream extraction that can leave a suffix. |
| Input snapshot identity | Enforce the byte limit on the actual read, including source growth after a size query, then parse that same owned immutable byte range. Where identity covers the JSON document, hash those exact bytes; do not parse one open and hash a later reopened file. Preserve existing publication/read scopes. Exercise source change/replacement during admission and delayed consumption without adding a JSON-specific file service or accepting a different snapshot. |
| Raw NUL | Reject raw zero bytes in the supplied document before parsing. The release [lexer treats NUL as end of input](https://github.com/nlohmann/json/blob/v3.12.0/include/nlohmann/detail/input/lexer.hpp), so a bounded range alone does not prove suffix rejection. Test a valid object followed by NUL and garbage. This byte check is admission policy, not another lexer; valid escaped `\u0000` remains a decoded string character subject to domain rules. Do not assume a strict-NUL option from newer documentation exists in 3.12.0. |
